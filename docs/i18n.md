# Internationalization guide

How the app is translated and how to keep it that way. The user stories behind it are in
[`i18n-user-stories.md`](./i18n-user-stories.md) (epic E16).

## Languages

| Code | Language | Locale used for numbers and dates |
|------|----------|-----------------------------------|
| `es` | Spanish (default and fallback) | `es-CO` |
| `en` | English | `en-US` |
| `fr` | French | `fr-FR` |
| `pt` | Portuguese (Brazil) | `pt-BR` |

- With no saved choice, the app opens in the language of the device if it is one of the four; any other language opens in Spanish.
- The user changes it in **Profile → Language**. The choice is saved on the device (`language.preference`) and applies at once, without restarting.
- A text missing in the chosen language is shown in Spanish, never as a raw key.

## Where things live

```
src/i18n/
  index.ts              i18next setup, resources, fallback
  languages.ts          supported languages, resolveLanguage()
  LanguageProvider.tsx  chosen language, saved on the device
  format.ts             localeTag(), numberMarks(), formatDate/DateTime/Time/Number
  locales/es.ts         reference dictionary (defines the shape)
  locales/en.ts, fr.ts, pt.ts
  tests/                dictionary, format and language tests
```

Dictionary keys are written in English and grouped by area (`auth`, `places`, `valve`, `adminUsers`, ...).
`es.ts` defines the shape; the other files are typed with it (`Translations`), so a missing or extra key is a compile error.

## Writing a text

In a React component:

```tsx
const { t } = useTranslation();
<Text>{t('places.list.title')}</Text>
<Text>{t('places.list.greeting', { name })}</Text>
```

Outside React (domain rules, validation, hooks, HTTP errors) use `i18n.t` from `src/i18n`:

```ts
import i18n from '../../i18n';
errors.title = i18n.t('tips.validation.titleRequired');
```

Rules:

- **Never write a visible text in a screen or a domain file.** The test `noHardcodedSpanish.test.ts` fails when a text with Spanish letters (á é í ó ú ñ ¿ ¡) is outside the dictionaries.
- **Constants with labels use getters**, so the text follows the language active when it is read (a plain object would freeze the language of the first import). See `DEVICE_STATUS_LABELS` or `STATUS_FILTERS`.
- **Plurals** use `_one` / `_other` keys and a `count` option: `t('places.list.count', { count })`.
- **Placeholders** are `{{name}}` and must be the same in every language.
- **Dates, numbers and money** never use `toLocale*String('es-CO')` directly; use the helpers in `format.ts` (`formatDate`, `formatDateTime`, `formatTime`, `formatNumber`) and `formatMoney` / `parseMoneyInput` for prices.
- **Service errors** come with a stable code in the `title` of the Problem Details body (for example `auth.account_locked`). The app maps the code to `errors.code.<code with dots as underscores>`; an unknown code falls back to `errors.kind.<kind>`. A new code in a service needs its text in the four dictionaries.

## Adding a key

1. Add it to `es.ts` in the right group.
2. Add it to `en.ts`, `fr.ts` and `pt.ts` (the compiler points to the ones you forget).
3. `npx tsc --noEmit` and `npx jest`.

## Adding a language

1. Create `locales/<code>.ts` typed with `Translations` and translate every key.
2. Add the code to `SUPPORTED_LANGUAGES` in `languages.ts`, the resource in `index.ts` and the option in `LanguageSection.tsx` (each language is named in itself).
3. Add its locale to `LOCALE_TAGS` and, if it writes numbers differently, to `numberMarks()` in `format.ts`.
4. Add it to the list in `tests/dictionaries.test.ts` and write a small test with its formats and error messages (see `french.test.ts`).

## Tests

- `dictionaries.test.ts`: every dictionary has the same keys and placeholders as Spanish, and no text is empty.
- `noHardcodedSpanish.test.ts`: no Spanish text outside the dictionaries.
- `format.test.ts`, `french.test.ts`, `portuguese.test.ts`, `englishTexts.test.ts`: formats, plurals and messages per language.
- `jest.setup.ts` puts the app in Spanish before every test, so a test that needs another language calls `changeLanguage('en')` itself.

## Known limits

- The title and body of notifications, the tariff disclaimer and the content of the tips are produced by the services or by the administrator, so they are shown as they were written.
- The French and Portuguese texts were written without a native review.
- `noHardcodedSpanish` only detects accented letters and `¿ ¡`; a Spanish text without them has to be caught in review.
